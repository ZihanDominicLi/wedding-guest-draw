# 婚礼现场同步答题功能实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在现有婚礼宾客登记、实时大屏和抽奖系统中加入 10 题同步答题，并把最终分数作为可选的抽奖筛选条件。

**Architecture:** 使用 PostgreSQL/Prisma 持久化答题场次、题目、参与者和答案；通过服务端状态机和服务器截止时间保证公平，SSE 只广播状态变化。宾客身份沿用登记记录签发的 HttpOnly 参与 token，抽奖锁定时把实际分数阈值和候选快照持久化。

**Tech Stack:** Next.js App Router 16、React 19、TypeScript、Prisma 7、PostgreSQL、Zod、Vitest、Playwright、现有 liveEventBus/SSE、Better Auth。

**Spec:** `docs/superpowers/specs/2026-09-24-live-quiz-design.md`

## Global Constraints

- 10 题，每题 1 分，满分 10 分。
- 默认每题 30 秒，后台可调整；截止时间由服务器判断。
- 每题只能提交一次；迟到或掉线跳过，不补答。
- 公布答案前不得向宾客端或大屏发送正确选项。
- 必须先完成现有宾客登记；不新增宾客账号体系。
- 普通抽奖资格保持兼容；只有启用成绩筛选的轮次使用答题分数。
- 所有状态转换、成绩更改和阈值回退写入审计日志。
- 修改代码前阅读仓库内 `node_modules/next/dist/docs/` 对应 Next.js 指南。

## Review Focus

- 截止时间边界：服务器判定 `receivedAt <= closesAt`，客户端时钟不能延长答题时间。
- 重复请求：同一参与者同一题只产生一条答案和一次得分。
- 保密性：未来题目、正确答案和解析不能通过公开 API、SSE 或页面源代码提前获得。
- 重启恢复：应用在 `LIVE` 或 `REVIEW` 状态重启后仍显示同一题和同一截止时间。
- 阈值回退：候选不足时逐分下降到 0，仍不足时不生成超过实际人数的中奖名额。

## 交付顺序与上线门槛

1. 先合并 Task 1-4，完成后用测试数据验证状态机和保密性。
2. 再合并 Task 5-6，进行主持人、手机和大屏三端联调。
3. 再合并 Task 7，确认普通抽奖回归测试通过后再启用成绩筛选。
4. 最后完成 Task 8、备份恢复演练和公网 HTTPS/Cloudflare Tunnel 烟测。
5. 正式使用前必须完成一次完整彩排：登记 20 人、10 题、断网/刷新、阈值回退、抽奖和结果导出；彩排数据清理需使用现有管理员删除功能并保留审计记录。

## 自审结果

- 10 题、每题 1 分、30 秒默认时限、不可修改、迟到跳过、答案公布时机均有对应任务和测试。
- 身份绑定、服务器时间、答案保密、重启恢复和阈值回退均有独立实现边界。
- 普通抽奖兼容路径明确，不会强制所有轮次依赖答题成绩。
- 计划没有要求未来题目、复杂题型、短信登录或多场租户，保持首版范围可控。
